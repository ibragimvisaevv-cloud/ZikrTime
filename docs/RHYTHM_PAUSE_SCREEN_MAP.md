# ZikrTime 0.8.29 — карта сохранения экранов и действий

Составлено по Android-реализации **0.8.28 (40)**, коммиту `c451791056a717846adad432f5b9d5884729d27e`, перед внедрением «Ритм и пауза» 8 ноября 2026. Исходный APK собран из `f59e2ad11281dee431fb82d2b603bae64cbb417f`; различие коммитов связано с последующими заметками/проверками. Локальная исходная точка: `baseline/rhythm-pause-0.8.28`. Рабочая ветка: `codex/rhythm-pause-0829`.

Новый бриф владельца заменяет прежнее визуальное направление. Эта карта описывает существующие действия, а не добавляет функции. Инвентаризация ограничена навигацией и представлениями Android; бизнес-логика, серверы, расчёты и религиозные наборы не подвергались новому аудиту.

В `Nav.kt` — **5 вкладок и 26 маршрутов**. Ниже они развёрнуты в **66 сценариев**, включая контекстные панели, отдельные Activity и виджеты. «Внедрено в коде» означает изменение представления напрямую либо через общие компоненты. Это не результат запуска. «Сверено по коду» подтверждает сохранение обработчиков и условий при сравнении исходников, «кадр» — отрисовку конкретного состояния, «действие» — выполненное взаимодействие с проверенным результатом. Ни один из этих уровней не заменяет другой.

## Текущий статус доказательств

Последний собранный APK — `8c2d2c02c0fb4138d8d9e63896529eec599b9c54`. Объединённый [прогон 42495677767](https://github.com/ibragimvisaevv-cloud/ZikrTime/actions/runs/42495677767): Android-сборка успешна; **10 UI-групп прошли, 7 не завершили проверки**. Debug-миграция и чистый первый запуск прошли. Три ошибки автотеста чтения/викторины/фокуса исправлены и ожидают повтора; четыре группы виджетов остановились при получении UI dump. Это не финальный успешный прогон. Источники, хеши и границы приведены в [статусе](RHYTHM_PAUSE_STATUS.md).

После этого прогона внедрена общая галочка выбранного состояния в 11 FilterChip / 9 UI-файлах. Оно требует нового APK и повторного запуска всех 17 групп. Все runtime-доказательства в таблице ниже пока относятся к `8c2d2c0`; на новый исходник они не переносятся. Целевая сверка этих 9 diff подтверждает сохранение callbacks, условий выбора, подписей и testTag; локальный compileDebugKotlin прошёл. Строка 13 больше не подразумевает побайтовую неизменность файла: изменено только представление выбора задержки.

Дополнительно выполнена целевая сверка `c451791 → 8c2d2c0` для 21 строки без запланированной новой проверки взаимодействий: **04, 05, 11, 12, 13, 16, 17, 18, 24, 26, 29, 31, 37, 45, 46, 49, 50, 51, 53, 54, 62**. Потерь обработчиков, прежних условий доступности и подписанных действий не обнаружено. Это проверка исходников, без аудита бизнес-логики и без выполнения перечисленных действий на устройстве.

- Системные разрешения, DatePicker/TimePicker, выбор мелодии/файла, dialer, launcher и внешние Telegram/карты остаются внешними или системными. Эта задача меняет собственные пояснения и входы в них.
- Все 30 снимков встроенной инструкции заменены реальными кадрами нового интерфейса из preview `42489586601`, исходник `0566585c761a20354fd2d443bf8644a480845359`. ## Целевой охват и границы верификации

Целевой уровень для каждого затронутого сценария: открытие/основное действие/возврат, светлая и тёмная темы; контекстные действия — на действительно выбранном объекте. Фактический прогон выполняет только перечисленные в отчёте действия и не объявляется полным достижением этого уровня. Для общих компонентов предусмотрены 320 dp, увеличенный шрифт 150%, поддерживаемые языки, поворот и открытая клавиатура. Чистый первый запуск выполняется отдельно от миграции **debug 0.8.28 → debug 0.8.29** с данными, созданными через UI. Подпись release APK проверяется независимо; установка release поверх версии на физическом телефоне из этого не следует.

Аппаратные и системные ограничения: фоновые сигналы и экран блокировки Samsung, OEM-экономия батареи, блокировка/пауза с реально выданными разрешениями, GPS/компас, установка и изменение размеров виджета в launcher. Внешние действия — звонки, сообщения, отзывы, исправления мест и платежи — не отправляются прогоном. Обычные экранные действия, не вошедшие в тесты, отмечаются как непроверенные отдельно, а не списываются на эти ограничения.

Результаты и ограничения отмечаются в двух последних столбцах с указанием артефакта/сценария. Наличие кода, успешная компиляция, screenshot и проверка взаимодействия — разные уровни подтверждения. Точность физических датчиков/фоновых сигналов на Samsung не выводить из эмуляторного скриншота.
