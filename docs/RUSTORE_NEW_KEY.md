# Подготовка новой подписи Android

Подготовлен отдельный процесс `.github/workflows/rustore-new-key.yml`. Он запускается только коммитом с `[rustore-new-key]` в ветке `codex/quran-reader-0814`. Пока новый пароль не сохранён владельцем, запускать его не нужно.

Требуется новый Actions secret `RELEASE_KEY_PASSWORD_V2`: отдельный случайный пароль длиной не менее 20 символов ASCII без пробелов. Владелец сохраняет пароль в менеджере паролей и в GitHub; пароль не передаётся в чат. Старый `RELEASE_KEY_PASSWORD` не изменять.

Процесс проверяет исходную готовую release-сборку, создаёт RSA-ключ 4096 бит либо восстанавливает уже созданный v2, проверяет шифрование и восстановление, сохраняет только зашифрованный ключ и публичный сертификат в ветку. Резервная копия шифруется AES-256-CBC с PBKDF2-HMAC-SHA256, 600000 итераций. Незашифрованный JKS существует только во временной папке, пароль передаётся инструментам через окружение и не попадает в артефакты.

После сохранения зашифрованной копии подписывается уже готовый APK: package и содержимое ZIP не меняются, Gradle не вызывается. Проверяются APK Signature Scheme v2 и точное совпадение сертификата. При повторном запуске используется тот же ключ; неверный пароль или неполная пара файлов приводит к остановке, а не к генерации ещё одного ключа.

Владелец получает подписанный APK, отчёт проверки и отдельный зашифрованный архив восстановления. Архив следует сохранить в двух местах, пароль — отдельно. После получения настоящего подписанного APK проверить его на телефоне. Загрузку и публикацию в магазине не считать выполненными автоматически.

Локальная проверка `python3 tools/ci/check_replacement_key.py` использует одноразовый тестовый ключ. Она проверяет шифрование/восстановление, сохранение идентичности, содержимое архива, отказ при неверном пароле и неполной паре файлов. Это не проверка боевого APK. Боевой ключ ещё не создан.

Дальнейшие сборки должны использовать v2. Старый процесс `rustore-sign-0817.yml` предназначен для прежнего сертификата и не используется для новой подписи. Никакие приватные ключи и пароли в открытом виде в репозиторий не добавлять.
