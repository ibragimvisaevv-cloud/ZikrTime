# Публикация проверенной Android-сборки

По поручению пользователя от 27 октября новые проверенные Android-сборки следует публиковать в GitHub Releases и добавлять прямую ссылку установки в README рабочей ветки. Не выдавать облачный файл за публичный GitHub-релиз. Main, магазины и iOS требуют отдельного поручения.

Прежняя схема проекта: `.github/workflows/android.yml`, job `release`, APK в Releases и ссылка `/releases/latest` в README. Для тестовой ветки используется отдельный prerelease, чтобы сохранить стабильный latest.

## Готовая публикация новой главной и тасбиха

Workflow `.github/workflows/publish-natural.yml` подготовлен для APK/AAB из успешного Android job 40476255211 и UI-артефакта 40477863659. Он проверяет SHA-256, прежний сертификат, прикладывает 16 снимков/видео/замеры и контрольные суммы, публикует `v0.8.3-natural.1`, затем повторно скачивает публичный APK и сверяет SHA-256. Повторных сборок и iOS-заданий нет.

Публикация запускается только push-коммитом с `[android-only] [publish-natural]` в рабочей ветке. Подготовительный коммит `[skip ci]` ничего не публикует.

## Требуемый доступ

Первая попытка встроенным GITHUB_TOKEN завершилась HTTP 403, прогон 40478896589. Согласно актуальной документации GitHub, публикация на коммите, который изменяет workflow относительно main, требует права Workflows: write; обычному GITHUB_TOKEN его выдать нельзя.

Создать fine-grained personal access token: владелец `ibragimvisaevv-cloud`, только репозиторий `ZikrTime`, Repository permissions `Contents: Read and write` и `Workflows: Read and write`, срок действия 30 дней. Сохранить значение в repository Actions secret `RELEASE_PUBLISH_TOKEN`. Не передавать значение в чат, код, README или логи.

Токен используется только в шаге создания релиза; скачивание CI-артефактов использует встроенный GITHUB_TOKEN с actions:read. Полные права администратора не нужны.

После добавления секрета: запустить подготовленную публикацию, убедиться в успешном скачивании публичного APK и обновить README, RELEASE_READINESS.md и PR фактической ссылкой. При существующем релизе workflow остановится, не перезаписывая файлы.

Документация: https://docs.github.com/en/rest/releases/releases#create-a-release
