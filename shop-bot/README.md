# Бот-кабинет продавцов магазина «Зикр-тайм»

Продавцы сами добавляют компанию, фото, товары и цены через Telegram-бота. Владелец одобряет новые
компании одной кнопкой; дальше правки продавца публикуются сразу (владелец получает уведомление и может
скрыть компанию). Приложение (Android и iPhone) берёт каталог из Yandex Object Storage:
`https://storage.yandexcloud.net/zikrtime-shop/catalog.json`.

## Как устроено

- `index.py` — логика бота (Python 3.12, без сторонних библиотек). Работает на **Vercel** (`api/webhook.py`): из российских облаков Telegram недоступен.
- Данные и фото — в Yandex Object Storage (быстро открываются у пользователей в России), доступ по статическому ключу сервисного аккаунта.
- Хранилище `zikrtime-shop`: `data/db.json` (база), `img/…` (фото), `catalog.json` (каталог для приложения).
- `.github/workflows/shop-bot.yml` — проверка (`test_bot.py`) и развёртывание при каждом изменении папки `shop-bot/`.

## Первый запуск (один раз)

1. **Бот:** в Telegram откройте @BotFather → `/newbot` → имя «Зикр-тайм Магазин», адрес, например `ZikrTimeShopBot` → скопируйте токен.
2. **Yandex Cloud:** console.yandex.cloud → войдите через Яндекс ID → создайте платёжный аккаунт (новым дают стартовый грант).
   Скопируйте ID каталога `default` (вверху страницы каталога).
3. **Сервисный аккаунт для развёртывания:** в каталоге → «Сервисные аккаунты» → «Создать» → имя `github-deploy`, роль `admin` →
   откройте его → «Создать новый ключ» → «Авторизованный ключ» → скачайте файл JSON.
4. **GitHub:** репозиторий → Settings → Secrets and variables → Actions → New repository secret:
   - `SHOP_BOT_TOKEN` — токен бота;
   - `YC_FOLDER_ID` — ID каталога;
   - `YC_SA_KEY` — всё содержимое файла JSON;
   - `SHOP_OWNER_USERNAME` — ваше имя в Telegram (без @);
   - `VERCEL_TOKEN` — vercel.com → вход через GitHub → Settings → Tokens → Create.
5. Actions → «Shop bot» → Run workflow. Когда станет зелёным — напишите боту `/start`: вы станете владельцем.

## Команды владельца

- Меню бота: «На проверке», «Все компании», в карточке компании — «Одобрить», «Отклонить», «Партнёр», «Скрыть».
- «Пригласить совладельца» — одноразовая ссылка: так можно создать компанию за партнёра и передать её ему.
- `/admin <id>` — добавить модератора (числовой id в Telegram).
# Банковская оплата для продавца

В Android кнопка «Кабинет продавца» открывает самостоятельный сайт. Для входа продавец запрашивает в личном чате бота команду `/webcode`. Одноразовый код действует пять минут. Сессия сайта ограничена одним часом и текущей страницей. При возврате из банка можно снова войти и обновить заказ. В Telegram доступны подача, модерация и просмотр операций. Выпущенные до перехода карточки сохраняют прежние условия. Размещение новой компании стоит 200 ₽ после одобрения. Товары входят в цену. По умолчанию продвижение стоит 100 ₽ за семь дней или 300 ₽ за тридцать дней. Владелец может менять эти два тарифа; сумма уже открытого заказа фиксирована.

Функция Yandex Cloud принимает банковские уведомления на `https://functions.yandexcloud.net/<id>?event=tbank`. Подпись, терминал, заказ, идентификатор операции и сумма проверяются на сервере. Окончательное состояние запрашивается у Т-Банка. Заказ и предоставление услуги сохраняются одной условной записью в закрытом бакете. Частичные возвраты и оплаченные заказы для магазина, снять или предоставить услугу которому невозможно, требуют ручной сверки в торговом кабинете. Окончательный полный возврат завершает предоставление оплаченной услуги. Просроченный или спорный заказ можно проверить кнопкой в кабинете продавца.

Перед включением владелец оформляет интернет-эквайринг для этой услуги, подключает СБП в торговом терминале при необходимости, согласовывает предмет и момент оказания услуги, устанавливает онлайн-кассу и налоговые реквизиты в соответствии со своим статусом. Интеграция отправляет в кассу данные одной услуги, e-mail покупателя и признак полного расчёта. Характер договора и порядок фискализации размещения/продвижения должен соответствовать передаче права на размещение или продвижение в момент подтверждения оплаты. Если договор предполагает аванс с последующим зачётом, требуется дополнительный кассовый сценарий до включения такой продажи. На сайте нужно опубликовать оферту с реквизитами продавца услуг, контактами, ценами, сроками, правилами возврата и ссылкой на политику обработки данных. Декларируйте внешнее платёжное решение в RuStore.

В GitHub Actions задайте секреты `TBANK_TERMINAL` и `TBANK_PASSWORD` и переменные `SELLER_OFFER_URL`, `TBANK_TAXATION`, `TBANK_TAX`. Значения двух налоговых параметров указывает владелец по данным кассы и документации банка. Адрес кабинета устанавливает деплой функции. До проверки тестового терминала, получения фискального чека в ОФД и подтверждения условий банком держите `TBANK_ENABLED` выключенной в боевом окружении. Задайте `TBANK_ENABLED=true` в тестовом окружении с тестовыми реквизитами для сквозной проверки, затем включите в рабочем окружении с рабочими реквизитами и разверните согласованную версию. При выключении новых продаж ранее открытые операции продолжают сверяться, если действующие ключи остаются доступными. Донат проекта имеет отдельное назначение.

Проверка без сети — `python3 shop-bot/test_acquiring.py`, `python3 shop-bot/test_bot.py` и `python3 shop-bot/test_miniapi.py`.

Источники: [инициализация платежа](https://developer.tbank.ru/eacq/api/init), [уведомления Т-Банка](https://developer.tbank.ru/eacq/intro/developer/notification/), [состояние заказа](https://developer.tbank.ru/eacq/api/check-order), [расчёты через интернет и кассовые чеки, ФНС](https://www.nalog.gov.ru/rn22/news/activities_fts/16545576/), [Telegram](https://core.telegram.org/bots/payments-stars), [требования RuStore, раздел 9](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps).


## СБП для самозанятого, версия 0.8.23

Для новых заказов по умолчанию выбран Robokassa. Подключается физическое лицо на НПД без регистрации ИП. «Робочеки СМЗ» необходимо связать с «Моим налогом» в кабинете провайдера. Стоимость размещения 200 ₽ назначает сервер. Продвижение использует сохранённые тарифы проекта. Услуга относится к размещению и продвижению в собственном приложении ZikrTime. Оплата товаров сторонних компаний через этот кабинет не принимается.

Кабинет по `SELLER_PORTAL_URL` является самостоятельным сайтом. Вход выполняется по одноразовому коду из Mini App («Аккаунт» → «Код входа на сайт»). Команда `/webcode` поддерживается для прежних пользователей. Сессия хранится в текущей вкладке и живёт один час, выход отзывает её на сервере. В Mini App можно управлять компаниями, продвижением и смотреть статусы. Для покупки цифровых услуг внутри Telegram действуют правила Telegram Stars.

Для подключения владелец регистрирует магазин в Robokassa как самозанятый, подтверждает реквизиты и вид услуги, включает «Робочеки СМЗ» и СБП. Перед активацией проверяет оферту, возвраты и получение НПД-чека. Обычный интернет-эквайринг Т-Банка требует статуса ИП, поэтому прежние инструкции по Т-Банку относятся только к уже имеющимся договорам и заказам.

Параметры облачной функции и процесса развёртывания:

| Переменная | Значение |
| --- | --- |
| `PAYMENT_PROVIDER` | `robokassa` (по умолчанию) |
| `ROBOKASSA_MERCHANT_LOGIN` | Идентификатор одобренного магазина |
| `ROBOKASSA_ENABLED` | `true` только после завершения подключения |
| `ROBOKASSA_NPD_RECEIPTS` | `true` после подключения «Робочеков СМЗ» |
| `ROBOKASSA_HASH` | `sha256`, тот же алгоритм указать в кабинете Robokassa |
| `ROBOKASSA_TEST_MODE` | `true` для тестов, `false` для рабочего магазина |
| `ROBOKASSA_TEST_PASSWORD1`, `ROBOKASSA_TEST_PASSWORD2` | Отдельные тестовые пароли, хранить как секреты |
| `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2` | Рабочие пароли, хранить как секреты |
| `SELLER_PORTAL_URL` | HTTPS-адрес облачной функции, устанавливает скрипт развёртывания |
| `SELLER_OFFER_URL` | HTTPS-адрес опубликованной оферты |

В технических настройках Robokassa указать `ResultURL = <SELLER_PORTAL_URL>?event=robokassa`, метод POST. `SuccessURL` и `FailURL` — сам `SELLER_PORTAL_URL`, метод GET. Простой возврат на сайт не подтверждает оплату. Сервер проверяет подпись уведомления, сумму с точностью до копейки, номер счёта, связанный заказ и режим оплаты. Повторное уведомление не продлевает продвижение повторно. Запись заказа использует существующую защиту от конкурентной записи. При недоступности сервиса статус остаётся ожидающим.

Тестовые и рабочие секреты разделены. Тестовая оплата получает статус `test_paid` и не включает размещение или продвижение. До заполнения настроек кабинет показывает, что приём оплаты готовится к запуску. Состояния ранее созданных заказов Т-Банка проверяются через прежний терминал даже после переключения новых заказов на Robokassa. Автоматические отмены и возвраты прежних заказов Т-Банка сохранены. Возвраты новых платежей Robokassa оформляются в кабинете провайдера с последующей сверкой услуги администратором.

Проверки без сети и денежных операций — `python test_acquiring.py` и `python test_robokassa.py` из `shop-bot`. Они проверяют подписи, подмену суммы, повторные уведомления, конкурентную запись, восстановление оплаты, отсутствие публикации после тестовой оплаты, совместимость старых заказов и read-only возврат на сайт.
